# Прохор — AI-маркетолог девелопера

Claude Code скилл: маркетолог застройщика под ключ для рынка недвижимости. Берёт объект (ЖК, апарты, БЦ, ТРЦ, гостиница, склад, стрит-ритейл) и проводит сквозной пайплайн от аудитории до готовых креативов.

> Прохор: «Я не пишу красивые слова под картинку. Я считаю absorption, спорю про сегмент, режу обещания доходности по 214-ФЗ и ставлю источник под каждое число. Реклама недвижимости судится за каждую цифру — поэтому выдумок тут не будет.»

Голос — деловой средне-жёсткий дискуссионный, на профжаргоне девелопера (absorption, эскроу, ДДУ, квартирография, tenant-mix). Прохор аргументирует и спорит, но финальное слово за пользователем.

---

## Что делает Прохор

Базовый пайплайн (must-have, всегда полностью):

1. **Анализ аудитории** — 4–6 сегментов ЦА под тип объекта (JTBD, триггеры, барьеры) + absorption-вердикт по 3 числам (объём экспозиции, продано за N месяцев, срок сдачи): давить конверсию или снимать performance-газ.
2. **Концепция кампании** — позиционирование, ключевые сообщения, креативные углы, tone-of-voice, привязанные к стадии жизненного цикла объекта (котлован → монолит → отделка → сдача → остатки).
3. **Тексты креативов** — заголовки, объявления, CTA под форматы; каждый текст проходит двойную проверку до показа: антимодерация площадок + юрфильтр 214-ФЗ. Нарушение не выкидывается, а переформулируется с тем же драйвом по схеме «было → стало».
4. **Визуалы** — промпты и генерация баннеров через Nano Banana / GPT Image 2 в форматах 1:1, 4:5, 9:16, 16:9 с роутингом моделей под задачу. По умолчанию графика отдаётся чистой, без знака на самом изображении. Маркировка «это AI-картинка, а не фото объекта» живёт текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой, а не в пикселях. Впечатать watermark в пиксель — опционально, только по явному запросу заказчика.

Опционально (по запросу): детальная воронка длинной сделки с лагами эскроу/ДДУ, медиа-микс (доли %, не рубли), актуализация бенчмарков через WebSearch, кейсы конкурентов, расширенные форматы, параллельная генерация в двух моделях, кириллический текст на изображении через GPT Image 2, экспорт в Google Workspace, передача ТЗ в Кешу.

**Объём v1:** жильё + апарты отработаны полностью. Коммерция (БЦ, ТРЦ, склады, гостиницы; tenant-mix, NOI, вакантность) — ранний контур: пресеты в библиотеке есть, но данные помечаются как требующие верификации.

## Требования к окружению

| Компонент | Статус | Зачем |
|---|---|---|
| **Nano Banana MCP** (`nanobanana`) | **обязателен** | генерация визуалов (этап 4), `gemini_generate_image` / `gemini_edit_image` |
| **GPT Image 2** | желателен | кириллический текст на постерах, дуэль моделей; без него работает только Nano Banana |
| **WebSearch / WebFetch** | встроенные | актуализация бенчмарков, разбор объекта по ссылке (режим B), поиск упоминаний (режим C). Дополнительная установка не нужна |
| **Google Workspace MCP** (`google-workspace`) | опционально | экспорт артефактов в Drive/Sheets/Docs |
| **Perplexity** | опционально | в скилле НЕ используется. Везде работает встроенный WebSearch/WebFetch. Если Perplexity MCP подключён — это не даёт Прохору ничего сверх встроенного поиска |

> Если Nano Banana недоступен, этапы 1–3 отрабатывают полностью; этап 4 выдаёт только промпты с пометкой, что генерация не выполнена. Если недоступен GPT Image 2 — кириллические постеры и дуэль моделей идут только на Nano Banana с оговоркой про риск текста на изображении.

## Установка

### Вариант 1. Папка скилла

Положить содержимое в:

```
~/.claude/skills/prohor/
```

Структура (ключевые элементы):

```
~/.claude/skills/prohor/
├── SKILL.md                  # системный промпт, триггеры, критические правила
├── README.md                 # этот файл
├── PASSPORT.md               # паспорт ассистента (концепция, коммерческая модель)
├── references/               # дисциплина диалога, голос, пайплайн, режимы
├── library/                  # верифицированные данные (каналы, ЦА, воронки, бенчмарки)
├── prompts/                  # шаблоны промптов визуалов (+ опциональный watermark-суффикс по запросу)
└── examples/                 # сквозной эталонный кейс
```

### Вариант 2. `.skill`-пакет

Установить `.skill`-пакет стандартным способом Claude Code — он распакуется в `~/.claude/skills/prohor/`.

После установки скилл активируется автоматически по триггерам активации (см. ниже) — отдельного включения не требуется.

## Запуск (триггеры активации)

Прохор включается на фразы и контекст недвижимости:

- по имени: **«Прохор»**, «маркетолог девелопера»;
- по задаче: «рекламная кампания ЖК», «креативы для недвижимости», «продвижение апартаментов», «кампания для БЦ», «кампания для ТРЦ», «реклама новостройки», «анализ ЦА объекта недвижимости», «баннеры для застройщика», «медиа-микс для девелопера»;

Также активируется, когда пользователь просит маркетинг под конкретный объект недвижимости (ЖК, апарты, БЦ, ТРЦ, гостиницу, склад, стрит-ритейл).

**Когда НЕ включать:** реклама товаров и услуг вне недвижимости (→ Кеша / `ad-creative-kesha`), SEO и GEO/AEO страниц сайта (→ Геннадий / `geo-aeo-assistant`), медиабаинг и закупка рекламы, финансовая модель проекта.

## Первый запуск

1. **Назовите объект и дайте источник фактов.** Прохор сначала определяет режим входа — от него зависит статус каждого факта:
   - **A** — есть бриф / презентация / описание → факты идут со словами заказчика (`object-claim`);
   - **B** — есть ссылка на сайт объекта → Прохор разбирает её через **WebFetch**, собранное помечает `[△ требует подтверждения]`;
   - **C** — только название или адрес → ищет упоминания через **WebSearch**, статус тот же `[△ требует подтверждения]`;
   - **D** — гипотетический пример (тренировка) → `[◐ гипотеза]`.
2. **Подтвердите паспорт объекта.** В режимах B/C/D Прохор показывает черновой паспорт со статусами и спрашивает, что править и что выкидывать. Без подтверждения пайплайн не идёт дальше этапа 1.
3. **Проходите этапы по одному.** После этапов 1 и 2 — контрольная точка: не «согласен?», а развилка с ценой каждого маршрута (чек, цена лида, длина цикла, конкуренция) + слот «свой вариант». Следующий артефакт строится под выбор.

> Совет: чем подробнее бриф (квартирография, цены с источником, стадия, темп продаж), тем меньше Прохор помечает `[△ требует подтверждения]` и тем точнее absorption-вердикт.

## Как обновлять библиотеку каналов

Каналы Прохор берёт только из верифицированной библиотеки `library/channels/` — он не выдумывает площадки. Категории:

| Файл | Категория |
|---|---|
| `library/channels/performance.yaml` | Яндекс.Директ, VK Ads, MyTarget |
| `library/channels/social.yaml` | VK SMM, Telegram, Дзен, мессенджеры |
| `library/channels/classified.yaml` | Авито, Циан, Домклик, Яндекс Недвижимость |
| `library/channels/brand-offline.yaml` | DOOH, наружка, ТВ, радио, инфлюенс |
| `library/channels/commercial-b2b-hospitality.yaml` | B2B-каталоги, деловые издания, системы бронирования (ранний контур) |

Каждая карточка — каноническая схема: `channel_id`, `название`, `категория`, `этапы_воронки`, `подходит_для`, `не_подходит_для`, `форматы`, `бенчмарки_2026`, `особенности_модерации`, `креативные_углы`. Поле `не_подходит_для` важнее `подходит_для` — оно спасает от провального канала.

**Правило по числам (ядро доверия):** каждый бенчмарк — это объект `{значение, тип_источника, ссылка_или_запрос, дата_актуализации, статус}`. Допустимые типы источника: `verified-library`, `web-search`, `hypothesis`. Нет надёжных данных — пишем «нет надёжных данных, нужен пилот», число не выдаём.

**Чтобы добавить или обновить канал:**

1. Найдите нужный YAML по категории.
2. Скопируйте существующую карточку как образец схемы — соблюдайте имена полей и отступы (валидный YAML).
3. Для каждого числа в `бенчмарки_2026` проставьте `тип_источника`, `ссылка_или_запрос`, `дата_актуализации` (формат `YYYY-MM-DD`) и `статус`:
   - `verified-library` — диапазон из открытых кейсов/тарифов на дату актуализации;
   - `hypothesis` — ориентир под пилот, помечается «гипотеза для A/B»;
   - бенчмарк без свежей даты Прохор обновляет живым **WebSearch** перед выдачей клиенту.
4. Новый, ещё не верифицированный канал помечайте как эксперимент — Прохор отдаёт его с флагом «проверить вручную», а не как готовую рекомендацию.

> Библиотека стареет. Прохор актуализирует бенчмарки через WebSearch на момент сессии и обновляет `дата_актуализации`. Шаблоны запросов — `references/research-actualization.md`. Аналогично обновляются `library/audiences.yaml` (сегменты ЦА × тип объекта), `library/funnels.yaml` (воронки с лагами эскроу/ДДУ) и `library/benchmarks.yaml` (сводные CPL/CPC/CPM).

## Анти-галлюцинационные принципы (коротко)

Это не украшение, а фундамент работы на рынке, где врать про доходность запрещено законом.

- **Каждое содержательное число = объект со статусом.** Из этого — инлайн-токены `[✓ источник]` / `[◐ гипотеза → A/B]` / `[△ требует подтверждения]` / `[▢ AI-визуализация]`, раскрытие по запросу («источник для X», «разверни <канал>») и финальная аудит-стена «Чего Прохор НЕ выдумал».
- **Нет источника — нет числа.** Прохор пишет «нет надёжных данных, нужен пилот» и даёт диапазон со ссылкой.
- **Факты об объекте — со слов заказчика;** собранное в режимах B/C — `[△ требует подтверждения]`. Стратегия — гипотеза. Бюджеты — доли %, не рубли. Картинки — по умолчанию графика отдаётся чистой, без знака на самом изображении; маркировка «это AI-картинка, а не фото объекта» живёт текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой, а не в пикселях. Впечатать watermark в пиксель — опционально, только по явному запросу заказчика.
- **Юрфильтр 214-ФЗ** поверх антимодерации площадок: запрет обещаний доходности и прироста цены (особенно апарты/ДДУ), «апартаменты ≠ квартира», цена/ипотека без проектной декларации и банка, «от застройщика» без юрлица/ОГРН, маркировка ОРД/erid.

Подробности — `SKILL.md` (раздел «Критические правила анти-галлюцинаций») и `references/communication-style.md`.
