# CHANGELOG — Прохор

История версий скилла «Прохор — AI-маркетолог девелопера». Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/); версионирование — semver.

Принцип ведения журнала: фиксируем, что собрано и почему, без чисел рынка без источника. Бенчмарки и доли каналов живут в `library/`, а не в журнале — здесь только перечень фич и решений сборки.

## [1.0.2] — 2026-06-05

### Changed
- **Пиксельный watermark больше не дефолт.** Раньше Прохор по умолчанию впечатывал знак «AI-визуализация» в каждое сгенерированное изображение (угловой полупрозрачный знак + дубль в имени файла). Теперь графика по умолчанию отдаётся **чистой**, без знака в пикселе — её можно сразу нести в рекламный кабинет. Честная маркировка «это AI-картинка, а не фото объекта» сохранена и живёт **текстовым токеном `[▢ AI-визуализация]`** в артефакте рядом с картинкой. Впечатать watermark в пиксель — опция по явному запросу заказчика под его ответственность. Затронуты `SKILL.md`, `references/image-generation.md`, `prompts/creative-prompts.md`, `references/output-templates.md`, `references/communication-style.md`, `references/pipeline.md`, `references/moderation-rules.md` и обзорные файлы; токен `[▢ AI-визуализация]` нигде не тронут.

### Added
- **Опция «Генерация креативов по референсам».** Этап 4 теперь умеет строить креатив не с нуля, а на **оригинальной графике объекта** — официальные рендеры/фото фасада с сайта застройщика, визуализации из брифа, генплан, планировки, логотип — поданные как визуальный референс (GPT Image 2 `--reference`, Nano Banana `gemini_edit_image` с `image_path` на реальный рендер). Узнаваемый ЖК на баннере вместо абстрактного «дома у воды». Дисциплина: права на исходник — на заказчике (чужие картинки из сети в референс не тащим), результат всё равно `[▢ AI-визуализация]`, поверх реального облика не дорисовываем несуществующее. Источник референса фиксируется в `campaign_matrix`. Опция выключена по умолчанию. Реализация — `references/image-generation.md` (раздел «Генерация по референсам»); затронуты `SKILL.md`, `references/modes.md` (сбор URL графики в режиме B), `references/pipeline.md`, `references/output-templates.md`, `PASSPORT.md`.

## [1.0.0] — 2026-06-04

Первая сборка Прохора. Сквозной конвейер под ключ для рынка недвижимости: анализ аудитории объекта → концепция кампании → тексты креативов с антимодерацией и юрфильтром 214-ФЗ → генерация визуалов через Nano Banana и GPT Image 2. Деловой средне-жёсткий дискуссионный голос на профжаргоне недвижимости.

Область v1: жильё (ЖК эконом / комфорт / бизнес / премиум / элит) + апарты и сервисные апартаменты. Коммерция (БЦ, ТРЦ, гостиницы, склады, стрит-ритейл) присутствует ранним контуром — пресеты каналов есть, но tenant-mix / NOI / вакантность вынесены в план развития.

### Added — ядро продукта

- **Must-have пайплайн из 4 этапов** (`references/pipeline.md`), всегда полностью:
  1. **Анализ аудитории** — 4–6 сегментов под тип объекта из `library/audiences.yaml` (JTBD, триггеры, барьеры) + калькулятор absorption rate: 3 числа от РОПа (объём экспозиции, продано за N мес, срок сдачи) → темп лотов/мес и остаток месяцев → управленческий вердикт «давим конверсию vs снимаем performance-газ», который меняет приоритет сегментов и каналов.
  2. **Концепция кампании** — позиционирование, ключевые сообщения, креативные углы и tone-of-voice, привязанные к стадии жизненного цикла объекта (котлован → монолит → отделка → сдача → остатки), а не абстрактные.
  3. **Тексты креативов** — заголовки, объявления, CTA под форматы; каждый текст проходит двойную проверку до показа (антимодерация площадок + юрфильтр 214-ФЗ); нарушение не выкидывается, а переформулируется с тем же драйвом по схеме «было → стало».
  4. **Визуалы** — промпты и генерация баннеров через Nano Banana / GPT Image 2 в форматах 1:1, 4:5, 9:16, 16:9 с роутингом моделей под задачу (`references/image-generation.md`, `prompts/creative-prompts.md`).
- **Верифицированная библиотека** как защита от выдумок:
  - каналы по 5 категориям — `library/channels/performance.yaml`, `social.yaml`, `classified.yaml`, `brand-offline.yaml`, `commercial-b2b-hospitality.yaml`;
  - сегменты ЦА × тип объекта — `library/audiences.yaml`;
  - воронки первички с лагами эскроу/ДДУ — `library/funnels.yaml`;
  - бенчмарки CPL/CPC/CPM со ссылкой и датой актуализации в карточке — `library/benchmarks.yaml`.
- **Режимы входа A/B/C/D** (`references/modes.md`): бриф/презентация, ссылка на объект (через WebFetch), название/адрес (через WebSearch), гипотетический пример. Всё собранное в режимах B/C/D помечается `[△ требует подтверждения]` и валидируется заказчиком до работы.
- **Опциональные функции по запросу**: детальная воронка длинной сделки, медиа-микс по каналам (доли %, не рубли), актуализация бенчмарков через WebSearch, кейсы конкурентов, расширенные форматы, параллельная генерация в двух моделях, текст на изображении через GPT Image 2 (кириллица), подгрузка ассетов заказчика, экспорт в Google Workspace, передача ТЗ в Кешу.

### Added — ядро доверия (анти-галлюцинации)

- **Единая структура «число = объект»** {значение, тип источника, ссылка-или-запрос, дата, статус}. Из одной структуры данных вытекают сразу три проявления: инлайн-токены, раскрытие источника по запросу и финальная аудит-стена. Словарь токенов — `references/communication-style.md`:
  - `[✓ источник]` — verified-library или web-search со ссылкой и датой;
  - `[◐ гипотеза → A/B]` — стратегическое предположение, требует теста;
  - `[△ требует подтверждения]` — данные, собранные Прохором, на подтверждение заказчиком;
  - `[▢ AI-визуализация]` — сгенерированное изображение, не фото объекта.
- **Жёсткое правило**: нет источника — число не выдаётся; Прохор пишет «нет надёжных данных, нужен пилот» и даёт диапазон со ссылкой. Бенчмарки — только из `library/benchmarks.yaml` или живого WebSearch; каналы — только из `library/channels/`.
- **Аудит-стена** «Чего Прохор НЕ выдумал» в конце сессии собирается автоматически из проставленных токенов: счётчик источников, блок ◐-гипотез, △-данные на подтверждение, число визуалов, помеченных `[▢ AI-визуализация]`.

### Added — отраслевая экспертиза

- **Калькулятор absorption rate → медиа-вердикт** (формула и пороги — `references/pipeline.md`): темп ниже плана → давим конверсию и спецусловия, не охват; распродаётесь быстро → снимаем performance-газ, готовим повышение цены и brand под следующую очередь.
- **Модель длинной сделки с лагами эскроу/ДДУ** (`library/funnels.yaml`): стадии первички показ → заявка → квалификация → показ/ВКС → бронь → одобрение ипотеки → ДДУ через эскроу → Росреестр; правило-предупреждение «цикл 3–9 мес → не убивай канал на второй неделе, brand дозревает через ремаркетинг».
- **Юрфильтр 214-ФЗ поверх антимодерации Кеши** (`references/moderation-rules.md`) с чётким разделением слоёв: антимодерация ловит стоп-слова площадок (Директ / VK / Telegram), Прохор добавляет отраслевую надстройку — запрет обещаний доходности и прироста цены (особенно апарты/ДДУ), «апартаменты ≠ квартира», цена/ипотека без проектной декларации и банка, «от застройщика» без юрлица/ОГРН, маркировка ОРД и erid. На каждый флаг — переформулировка с тем же драйвом, не «нельзя».
- **Карта триггеров и барьеров по сегментам** с ипотечным и инвест-слоем в `library/audiences.yaml`: отраслевые JTBD вместо общих (семья комфорт — школа в пешей доступности, двор без машин, евро-планировка; инвестор апарты — угол на ликвидность локации и УК, т.к. доходность обещать нельзя по закону).
- **Честная маркировка «AI-визуализация»** (`prompts/creative-prompts.md`): по умолчанию графика отдаётся чистой, без знака на самом изображении. Маркировка «это AI-картинка, а не фото объекта» живёт текстовым токеном `[▢ AI-визуализация]` в артефакте рядом с картинкой, а не в пикселях. Впечатать watermark в пиксель — опционально, только по явному запросу заказчика под его ответственность. Прямая митигация самого чувствительного риска рекламы недвижимости — «картинку выдают за фото объекта».

### Added — дискуссионность

- **Голос Прохора** (`references/character-voice.md`): по умолчанию НЕ соглашается, спорит по сути по 3-итерационной механике Кеши, держит позицию или меняет её вслух при сильной фактуре о проекте. Дисциплина диалога и образовательный слой без занудства — `references/communication-style.md`.
- **Развилки А/Б/свой вариант на контрольных точках** вместо «Продолжаешь?»: после этапов 1 и 2 — резюме + ровно 2 именованных маршрута с трейд-оффом (чек, цена лида, длина цикла, конкуренция) + слот для своего варианта, через AskUserQuestion; следующий артефакт строится под выбор.
- **Режим «Челлендж»**: банк типовых возражений девелопера с фактурой (например «у нас элитка, VK не работает», «инвесторы не в соцсетях», «баннер с ценой не пройдёт»), отработка по алгоритму Кеши.

### Changed

- **Perplexity заменён на встроенный WebSearch / WebFetch по всему скиллу** (актуализация бенчмарков, поиск кейсов, тренды — WebSearch; вытаскивание данных по ссылке на объект в режиме B — WebFetch). Шаблоны запросов — `references/research-actualization.md`. Причина: Perplexity MCP в окружении не подключён; без этой правки скилл ссылался бы на несуществующий инструмент. Историческая концепция v1.0 в `PASSPORT.md` ещё упоминает Perplexity и единый `channels.yaml` — источник правды для сборки остальных файлов — `SKILL.md` и блюпринт докрутки, а не устаревшие места паспорта.

### Notes

- Библиотека каналов разнесена по 5 файлам в `library/channels/` (вместо единого `channels.yaml` из паспорта).
- Юрфильтр 214-ФЗ слит с антимодерацией Кеши в один файл `references/moderation-rules.md` с разделением слоёв ответственности.
- Идеи-дубли схлопнуты в одно ядро доверия: светофор токенов + аудит-стена + раскрытие источника + карточка канала + бенчмарк-движок = одна структура «число = объект со статусом».
- Вынесено за пределы v1: пресеты ×6 и движок коммерции (tenant-mix, NOI, ставка капитализации), QR-раздача через Google Workspace, мульти-ratio пере-кадрирование и live-правки фасада голосом.
